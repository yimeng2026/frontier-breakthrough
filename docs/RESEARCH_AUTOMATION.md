# 全球前沿定期消化机制

## 目标

每周形成一次“新增证据—可用资产—最小复现—上游回馈”闭环，而不是只生成新闻摘要。拟议节奏为每周一 09:17，时区 `Asia/Shanghai`。实际任务编号、启用状态和下次触发时间以创建后回读为准；未得到额度确认前不创建或启用。

## 检索面

1. AI for Math、AI for Science、AI for Biology、AI for Physics 的原始论文、官方仓库、模型卡和公开数据。
2. 中国科学院科学前沿极限突破计划、NSFC、DOE、NSF、欧盟 RAISE、日本 MEXT 等官方更新。
3. AI 基础能力中真正影响科学实践的变化：形式化、程序搜索、自动实验、评价、数据治理与开放模型。
4. 知乎等社区只作为问题线索；关键主张回到论文、代码、数据或官方文件。

## 每周流程

- **发现**：记录检索时间、查询词、来源和检索失败；同一结果去重。
- **筛选**：优先与现有项目互补的资产，标记 `peer_reviewed / official_artifact / preprint / watch`。
- **消化**：回答“新增了什么证据、仍缺什么验证、能借用哪部分、我们能回馈什么”。
- **验证**：一次只选择少量可在本机或公开服务完成的样例，固定版本和输入。
- **回馈**：形成真实复现、对照、适配或文档；没有实际贡献时明确写“本周未回馈”。
- **归档**：报告写入 `reports/YYYY-MM-DD.md`，更新目录和本地状态，保留负结果。

## 报告固定栏目

1. 本周重要变化及原始来源；
2. 与现有项目的引用和依赖关系；
3. 可本地化/可外部复用/仅观察的决策；
4. 已完成的验证与未完成的验证；
5. 对上游或设施方可提供的具体帮助；
6. 下周一个最小可检验问题；
7. 检索失败、访问限制与利益冲突。

## 使用约束

这类开放调研会持续消耗模型额度；若调用插件，也会按配置频率持续消耗相应额度。任务不依赖浏览器登录状态，不自动推送、不自动建看板、不自动给外部维护者发消息。每周新会话独立执行，但共享本项目文件；失败不得被后续摘要覆盖。

## 防止“资讯膨胀”

- 连续四次没有新证据或可执行动作的观察项，降频或移出重点。
- 新工具若没有与既有工具不同的验证价值，不单开安装环境。
- 禁止以项目数量、论文数量或代理调用次数代替科研成效。
- 大科学设施不做本地化承诺，以公开结果、可复现接口和互补贡献对接。
